# Project Context: Computer Science Master's Thesis

This repository contains the Master's Thesis project of Daniil Sanzharov. The research focuses on automated plastic waste detection in aquatic environments using deep learning, optimized for Edge Computing.

## Project Structure

- `code/`: Python scripts and Jupyter notebooks for training and evaluating Computer Vision models.
  - Primary models: YOLO26 (via Ultralytics).
  - Datasets (in `data/`, git-ignored): FloW-img (`data/flow_img/`, `data/flow_img.yaml`; unlabeled FloW video frames in `data/video_frames/`) and UCWD, coastal UAV litter with 7 classes (`data/ucwd/{train,val,test}/{images,labels,annotations.json}`, `data/ucwd.yaml`). Each split keeps a COCO `annotations.json` whose category ids match the YOLO class ids, used for COCO metrics.
  - `ssod/`: Semi-Supervised Object Detection (SSOD) pipeline components.
    - `ablation.py`: Overnight ablation runner for the Mean Teacher pipeline, organised in named batches of short runs from shared warm-up weights (skip/resume, per-batch `summary.csv`, reference runs, label-fraction subsets with their own warm-ups, step-matched GT-only controls). Batches, results and the adopted default configuration (4,800 pseudo-labelled frames per epoch, soft weights, Teacher EMA 0.9996, no GT tail) are documented in `ABLATION.md`.
    - `export_results.py`: Read-only exporter that consolidates Mean Teacher run results (and the naive self-training baseline) into raw-number CSV tables in `paper/exp-results/` for the Typst thesis (main comparison, settings summary and per-epoch curves, components, architectures, label fractions). See `ABLATION.md`.
    - `dataset.py`: Dual dataset handler (`SSODDatasetHandler`) and epoch-aware sampler (`SSODSampler`). Supports simultaneous loading of annotated Ground-Truth (train & val) and an unlabeled pool (`UnlabeledDataset`, a fresh image list each epoch via `set_pl_images`; no label files), strict selective augmentations (HSV, scale, translate, fliplr on both; Mosaic on GT only, automatically closed during the last 10% of epochs; optional strong Student augmentation on unlabeled images — stronger HSV, Gaussian blur, random erasing that records its patches; all other augmentations disabled), a weak Teacher view for unlabeled images (`teacher_img`: same geometry as the Student view, no photometric augmentation), epoch sequencing with all GT shuffled with the unlabeled images by default (optional GT tail via `tail_ratio`, formerly 25%) and optional GT repetition (`gt_repeat`), and `is_pseudo` batch collation with stacked Teacher views, erased patches (`erase_boxes`) and GT `pl_weight` of 1.
    - `mean_teacher.py`: Semi-supervised Mean Teacher training pipeline (`MeanTeacherTrainer`) with online Size-Stratified Ground Thresholding. Supports supervised warm-up on Ground-Truth data, initializing Student from Teacher weights, initial per-size-bin score histograms from a uniform pool sample after the warm-up, epoch-0 baseline evaluation of the starting Teacher, per-step pseudo-labelling of the batch's unlabeled images by the current Teacher, per-step Teacher EMA then score-histogram EMA updates (same decay), Student training using YOLO default detection loss via `WeightedDetectionLoss` (YOLO26 E2E one-to-one/one-to-many gains pinned to their end-of-warm-up values; optional per-box pseudo-label importance weights; optional unsupervised weighting $\lambda_u$ with linear ramp-up), optional fresh uniform per-epoch sample of the unlabeled pool (`pl_images_per_epoch`), per-epoch Teacher evaluation on GT validation split logging Ultralytics and COCO metrics plus pseudo-label counts, size-bin shares, mean weights and mean thresholds, the histogram log (`histograms.csv`, `histograms/epoch_<k>.npz`), histogram state in checkpoints, and checkpoint selection via Ultralytics fitness. Includes Typer CLI. The previous offline pipeline (one pseudo-labelling pass per epoch) is at git tag `offline-ssgt`.
    - `losses.py`: `WeightedDetectionLoss`, a `v8DetectionLoss` whose foreground (classification, IoU, DFL) terms are importance-weighted per box by `batch["pl_weight"]`; background anchors and normalisation are unchanged, so weight-0 boxes act as ignore regions. Identical to the stock loss without weights.
    - `metrics.py`: Standalone COCO evaluation and prediction ID harmonization module (`evaluate_coco`, `fix_prediction_ids`), organised as small single-purpose functions with `evaluate_coco` composing them (load harmonised predictions → `run_cocoeval` → `coco_metrics` with `peak_f1`), computing multi-scale AP (`mAP_s`, `mAP_m`, `mAP_l`), AR, and peak $F_1$ score via `pycocotools.cocoeval`, with the COCO size bins applied at the network input scale (`imgsz`, per image; `imgsz=None` for original pixels); Ultralytics' 1-based category ids for non-COCO datasets are mapped back to the GT's YOLO class ids (unknown ids to a default category) without rewriting `predictions.json`; peak $F_1$ uses the class-averaged precision-recall curve.
    - `pseudo_labeling.py`: Online pseudo-labelling (Size-Stratified Ground Thresholding), organised as small single-purpose functions. `OnlinePseudoLabeler.label()` labels a batch's unlabeled images from their weak Teacher views: 2-view candidate inference on the GPU tensor (native + horizontal flip, merged by class-wise NMS), COCO size bins by box area in the batch image (network input scale), thresholding by the bin's threshold, threshold-aware per-box weights on by default (0 at the bin's threshold, rising linearly to 1 at the bin's object mode), dropping boxes mostly erased in the Student view, and appending the boxes to the batch targets (kept sorted by image). `ScoreHistograms` keeps the EMA of each bin's normalised candidate score histogram (one shared histogram when size bins are off) and derives the ground thresholds (valley between the noise and object modes, with a fallback threshold when no valley exists). `PseudoLabelLog` gives the per-epoch results columns and writes the histogram log. Also uniform image sampling of the pool.
    - `recompute_coco.py`: Recomputes stored COCO metrics from saved per-epoch `predictions.json` without re-running models (Mean Teacher `results.csv` `coco/*` columns, the UCWD full-label `eval_best.csv`, the naive self-training YAMLs, and each ablation batch's `summary.csv`); originals kept as `*.before_size_norm.csv`, `--dry-run` to preview.
    - `utilities.py`: Project-wide structured logging (`get_logger`) and shared utilities (`input_scale`, the letterbox factor to the network input).
  - `plot_results.py`: Figures of thesis section 3 (`label_efficiency`, `training_curves`, `caps_images_seen`, `ssgt_histograms`, `ablation_forest`, `architectures`) written as PDFs to `paper/figures/` from the run folders (`uv run python code/plot_results.py all`).
- `tests/`: Automated pytest unit and integration test suite covering SSOD augmentations, samplers, EMA updates, loss functions, COCO evaluation, and dataset lifecycles. Shared fixtures live in `conftest.py`; pytest config (including `pythonpath` and the `slow`, `integration` and `needs_artifacts` markers) is in `pyproject.toml`. Run with `uv run pytest`, or `uv run pytest -m "not slow"` for the fast subset.
- `paper/`: Raw Typst files for the thesis paper and conference abstracts.
  - `ВКР-Магістр-Санжаров.typ`: Main thesis document.
  - `sources.bib`: Bibliography in BibLaTeX format.
- `runs/`: Output directory for model training and evaluation results.

## Foundational Mandates & Instructions

- **Academic Integrity:** All Typst files (`paper/*.typ`) are **READ-ONLY**. You must not modify the content, structure, or arguments of the thesis. The only exception is proofreading or grammar correction, and even then, only when **explicitly** directed by the user for a specific section.
- **SAHI Framework:** Although SAHI (Slicing Aided Hyper Inference) is present in some legacy scripts and was tested, it **should not be used** for further development or production inference. Experimental results showed poor performance on this specific dataset compared to native YOLO26.
- **Dependency Management:** Always use `uv` (e.g., `uv add`, `uv run`, `uv lock`). Never use `pip` or `venv` directly. The project environment is located in `.venv/`.
- **Notebooks:** When working with notebooks in `code/`, ensure the kernel is set to the `.venv` created by `uv`.
- **Past-experiments:** `code/noisy_student_pipeline/` and `code/sahi_experiments` contain code for the past experiments that demonstrated inadequate results. They can be looked up for reference what was done before, but they should not be used as reference for style or design of the current and future code.
